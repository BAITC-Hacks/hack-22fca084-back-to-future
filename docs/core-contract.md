# Контракт расчётного ядра

Ядро — чистая библиотека `city_core`, владелец ветки `doszhan`.
Сервер Алишера импортирует библиотеку; клиент не повторяет формулу Score.

- Вход: последовательность `Selection(measure_id, district_id=None)`.
  Идентификаторы мер: `M1`–`M14`; районов: `esil`, `almaty`, `saryarka`,
  `baikonur`, `nura`. Для городской меры район отсутствует.
- `get_catalog()` возвращает неизменяемый каталог исходных показателей,
  весов, районов, мер, несовместимостей и синергий из датасета кейса.
- `validate_scenario(selections)` возвращает все обнаруженные нарушения
  с кодом, русским сообщением и идентификаторами затронутых мер.
- `evaluate_scenario(selections)` при нарушении возвращает ошибки и
  `result=None`. Невалидный сценарий не получает даже частичный Score.
- Валидный результат содержит бюджет, канонически упорядоченные решения,
  исходное и итоговое состояние города, district_changes с готовыми дельтами
  районных баллов, changes с изменениями показателей и вклады мер
  и синергий. Вклад — изменение показателя до ограничения 0–100, а не
  независимый вклад в нелинейный городской Score.
- `baseline()` считает исходное состояние отдельно; пустой пользовательский
  сценарий при этом остаётся невалидным.

Расчёт использует `Decimal`, без промежуточного округления. JSON-представление
сохраняет десятичные числа строками; отображение до двух знаков делает клиент.
Порядок решений не меняет результат. Каталог не изменяется при расчёте.

Горизонт — 8 кварталов. Сначала суммируются реализованные эффекты и фиксированные
синергии, затем применяется clip. Штраф учитывает значения строго меньше 40.
Данные районов синтетические; это не географическая статистика реальной Астаны.

Контрольные результаты: база `52.55768`; пример из кейса за 95 единиц —
`56.54307`, без критических показателей после применения мер.
